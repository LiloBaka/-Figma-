# Задание для Codex: создать рабочий Figma-плагин Illustration Builder

Ты работаешь в корне предоставленного репозитория. **Не ограничивайся планом: реализуй, протестируй и оставь запускаемый проект.** Используй `docs/source_handoff.md` и три PDF в `original_briefs/` как исходные требования. Структурированные данные в `spec/`, оригинальные SVG в `assets/` и SVG-шаблоны в `references/` — обязательные исходные материалы.

## Приоритеты

1. Рабочий Figma-плагин на TypeScript с UI (React или более простой UI при необходимости), локальным импортом библиотеки и вставкой векторной сцены на страницу Figma.
2. Два сценария: (а) ввод заголовка/метафоры → подбор валидных assetIds и шаблона; (б) выбор и поиск ассетов по тегам/названию. Начни с offline deterministic mapping, чтобы плагин полностью работал без API-ключа; AI gateway делай опциональным.
3. Управление сценой: выбрать L/S и шаблон, добавить/удалить/дублировать, изменить порядок, переместить, повернуть, переключить `main/background` при наличии исходного SVG-варинта. Не предоставлять произвольный scale или редактирование paths.
4. Готовая сцена на канвасе Figma должна состоять только из оригинальных SVG-контуров; **не** заменять path на image fill, canvas screenshot, raster, внешне сгенерированное изображение.
5. Экспорт SVG через Figma Plugin API, проверка наличия vector `<path>` и отсутствия SVG `<image>` / base64 raster.
6. Минимум 3 работоспособных demo-scenes с различными шаблонами/ролями; инструкция установки, тесты, скриншоты или gif для демонстрации.

## Жёсткие правила

- Оригинальные `assets/**/*.svg` не изменять. При импорте в сцену допускаются лишь трансформации **целого объекта** и обоснованное применение утверждённой палитры.
- Не сочинять 20 независимых assetIds: в `spec/assets.json` подтверждены 10 базовых типов × 4 варианта; два мелких Vector пока в unclassified.
- Не подменять цвета guessed semantic map. Сначала полноценный режим «оригинальные цвета» + переключение между предоставленными variant SVG. Для дополнительных цветовых схем создать расширяемый механизм semantic tokens, но не изображать произвольную перекраску как соответствующую референсам. Если палитра отсутствует, явно отключить её в UI или обозначить как экспериментальную.
- `references/templates/*.svg` — целые готовые иллюстрации, НЕ 6 точных slot manifests. Изучи их, создай свои доступные layout presets, документируй inferred параметры. Визуально сравни с оригиналами.
- `spec/scene.schema.json` служит контрактом. Храни сцену в plugin data / clientStorage и восстанавливай её.
- При импорте нескольких SVG учитывай конфликты `defs`/`clipPath` ids. Используй Figma `figma.createNodeFromSvg` как контролируемый импорт, применяй изменения на уровне объектных нод.
- В Figma пользователь потенциально может изменить path вручную; не утверждай, что это полностью технически заблокировано. Можно ставить pluginData и проверять целостность.
- Не клади API-ключи в код plugin UI. Для AI gateway поддержи env, валидацию по allowlist assetId/templateId, graceful fallback.

## Порядок выполнения

**Этап 0:** запусти `python3 scripts/validate_assets.py`. Изучи manifests и референсы; составь `docs/ASSUMPTIONS.md` с неподтверждёнными местами.

**Этап 1:** создай `manifest.json`, `package.json`, TypeScript build, Figma `code.ts` и UI, с инструкцией npm install/build и импортом `manifest.json` в Figma Desktop. Плагин должен уметь показать 10 базовых asset previews (предпросмотр из исходных SVG), искать, добавлять в сцену, вставлять в Figma и экспортировать.

**Этап 2:** добавь операции с объектами и шаблонами. Геометрию сцены опиши явно в JSON/TypeScript на каноническом холсте 1200x630 для MVP; не объявляй это доказанным native L/S. Для L/S задай документированные scale/offset слотов и safe area. Если масштабирование нарушает правила, используй строго фиксированные пресеты из существующих SVG вариантов.

**Этап 3:** реализуй подбор по тексту через словарь тегов и синонимов, чтобы не зависеть от сети. Опционально добавь backend для AI c JSON schema и allowlist; даже при ошибке AI должен сработать deterministic fallback.

**Этап 4:** тесты: валидация 40 SVG хешей, экспорт не содержит `<image>` / raster, верные роли, 2 формата, 3 шаблона, layer order, восстановление сцены. Проверить ошибки Figma API и показать реальные результаты тестов.

**Этап 5:** подготовь `README.md` для запуска результата, архитектуру, список использованных AI-инструментов, ≥3 demo compositions, перечень известных ограничений. Не скрывай неопределённость исходников и отсутствие утверждённых color token maps.

## Acceptance checklist

- [ ] Установка и открытие Figma-плагина по README
- [ ] Каталог 10 типов × 4 версии SVG, из source bytes
- [ ] Ручная композиция на холсте Figma: add / move / rotate / duplicate / delete / reorder
- [ ] Текстовый сценарий без API работает офлайн
- [ ] Роли `main/background` и L/S; без свободного scale
- [ ] Экспорт SVG с сохранением векторности
- [ ] Scene persistence и обработка ошибок
- [ ] Три демо, документация, запуск тестов
- [ ] Чёткое объяснение, чего нельзя подтвердить из исходников

Сделай максимально завершённый реально запускаемый MVP. Если что-то нельзя доказать, используй безопасное ограничение и укажи это, вместо выдумывания данных. Не проси пользователя заново выгружать файлы без конкретной причины.
