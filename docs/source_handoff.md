# Технический handoff: конструктор векторных иллюстраций

## 1. Цель

Собрать работающий сервис (предпочтительно Figma-плагин) для создания иллюстраций из **готовой библиотеки из 20 SVG-элементов**. Пользователь описывает метафору/заголовок или выбирает нужные объекты, а сервис предлагает и собирает композицию в заданном формате и палитре.

Ключевое ограничение: сервис **не генерирует новые иллюстративные объекты**. Итог состоит только из исходных векторных объектов и их заранее подготовленных фоновых вариантов. AI допустим только для интерпретации метафоры и выбора объектов/раскладки.

## 2. Рекомендованный формат продукта

Сделать Figma-плагин. Он использует существующую библиотеку Figma/SVG, создаёт редактируемые векторные слои на холсте и экспортирует SVG без потери векторности. Отдельный веб-интерфейс допустим только если он умеет сохранять нативную структуру SVG и экспортировать результат без растрирования.

## 3. Входные данные

### 3.1. Способы запуска композиции

1. **По метафоре:** пользователь вводит заголовок или короткое описание, например «совместная работа», «фокус», «обучение». AI возвращает 2-4 релевантных объекта и один из разрешённых шаблонов композиции.
2. **По объектам:** пользователь ищет и выбирает элементы по имени/тегам, затем вручную собирает композицию.

### 3.2. Управление сценою

- выбор формата: `L` и `S`;
- выбор цветовой схемы;
- добавление, удаление и дублирование объекта;
- перемещение по холсту;
- поворот объекта;
- изменение порядка слоёв;
- переключение состояния объекта: `main` (главный) / `background` (фоновый);
- экспорт итоговой композиции в SVG.

## 4. Жёсткие визуальные правила

| Разрешено | Запрещено |
|---|---|
| менять композицию и взаимное расположение объектов | менять пропорции объектов относительно друг друга |
| менять роль объекта: главный или фоновый | редактировать сам объект или его внутренние элементы |
| применять одну из утверждённых цветовых схем | «собирать» новый объект из частей существующих |
| двигать, поворачивать, копировать, удалять и менять z-index | нарушать утверждённую цветовую схему |

### Важная интерпретация правил

- Масштаб объектов должен браться из предустановок библиотеки/шаблона. Свободный `scale` в UI не давать; при необходимости использовать только пресеты `main` и `background`.
- Перекраска применяется к семантическим токенам SVG, а не к случайным hex-значениям. Контуры, тени, акценты и заливки должны маппиться отдельно.
- Объект вставляется как целый `<g>`/instance. Нельзя разбивать его на части, редактировать path или смешивать части нескольких объектов.

## 5. Визуальная система из материалов

### Форматы и палитры

- Есть два формата: **L** и **S**. Размеры должны задаваться пресетами; в материалах также указано, что конструктор автоматически подбирает соответствующие элементы.
- В исходных материалах показаны как минимум три фона/палитры: светло-фиолетовая, персиковая и светло-бирюзовая.
- Для каждой палитры есть согласованные наборы цветов для главных объектов, фона и акцентов. Не подменять их произвольными цветами: вынести в `palette.json`/Figma Variables.

### Типы объектов

В библиотеке видны следующие категории, которые нужно завести как теги для поиска и AI-подбора:

- обучение/чтение: раскрытая книга, блокнот, ручка;
- технологии/решение задач: телефон с пазлами, отдельные пазлы;
- продуктивность/доступ: кошелёк/кардхолдер, монета/жетон;
- фокус/аудио: наушники;
- рабочее место: настольная лампа;
- идеи/творчество: ваза с цветами;
- поддержка/декор: их одноцветные фоновые варианты.

У каждого предмета должны быть минимум два заранее подготовленных представления: `main` и `background`. Фоновый вариант используется как поддерживающий слой, с упрощённой монохромной обработкой согласно библиотеке.

## 6. Данные и структура библиотеки

### Манифест одного ассета

```ts
type Asset = {
  id: string;                    // stable slug, например phone-puzzle
  name: string;
  tags: string[];                // ["technology", "problem-solving"]
  svg: string;                   // исходный SVG или ссылка на компонент
  allowedRoles: ("main" | "background")[];
  roleVariants: {
    main: Variant;
    background?: Variant;
  };
  paletteBindings: Record<string, string>; // semanticColor -> variable/token
  nativeBounds: { width: number; height: number };
  allowedRotations: number[];    // если библиотека ограничивает поворот
};

type Variant = {
  svg: string;
  scalePreset: "main" | "background";
  tokenMap: Record<string, string>;
};
```

Не хранить SVG как raster/data URL и не преобразовывать его в canvas. При импорте нормализовать `viewBox`, сохранить группы/paths и привязку к семантическим цветам.

### Сцена

```ts
type Scene = {
  format: "L" | "S";
  paletteId: string;
  items: Array<{
    id: string;
    assetId: string;
    role: "main" | "background";
    x: number;
    y: number;
    rotation: number;
    zIndex: number;
  }>;
};
```

`scale` намеренно отсутствует в сцене: размер определяется вариантом и шаблоном, чтобы не нарушать пропорции исходной системы.

## 7. Алгоритм сборки

1. Принять заголовок/метафору или список ассетов.
2. Если введена метафора, AI возвращает строго валидный JSON: `assetIds`, `roles`, `templateId`, `reason`. До применения проверить IDs по манифесту.
3. Выбрать шаблон для формата `L`/`S`: 1 главный объект + 0-3 фоновых; либо 2-3 главных объекта, если шаблон разрешён.
4. Расставить объекты по слотам шаблона, применить только их `roleVariant` и токены выбранной палитры.
5. Выполнить валидацию: нет изменённых paths; нет свободного scale; все token bindings разрешены; объекты не выходят за safe area; нет неразрешённых пересечений/повторений.
6. Показать пользователю редактируемую сцену. Ручные действия разрешены только из раздела 3.2.
7. Экспортировать DOM SVG, сохранив `viewBox`, `<path>`, `<g>`, градиенты/defs и порядок слоёв.

## 8. UX Figma-плагина

### Экран 1 - Create

- поле «Метафора или заголовок»;
- кнопка «Собрать композицию»;
- переключатель `L / S`;
- выбор палитры;
- 2-3 предложенные композиции с кратким объяснением выбора.

### Экран 2 - Library

- поиск по названию и тегам;
- фильтры: `main`, `background`, категория;
- превью каждого объекта в текущей палитре;
- добавление в текущую сцену.

### Экран 3 - Scene

- список слоёв и действия: вверх/вниз, дублировать, удалить;
- `main/background` только если у ассета есть соответствующий вариант;
- перемещение и поворот через Figma; масштабирование заблокировать или снапить к допустимому пресету;
- кнопки «Экспорт SVG» и «Вставить на страницу».

## 9. Техническая реализация

- **Runtime:** Figma Plugin API + TypeScript + React для UI.
- **SVG:** `figma.createNodeFromSvg()` или эквивалентный контролируемый импорт; вставлять как векторные слои, не как image fill.
- **Tokens:** Figma Variables/Styles либо локальный манифест токенов. Перекраска осуществляется через переменные/semantic token mapping.
- **AI gateway:** отдельный серверный endpoint. Он не имеет права возвращать SVG/path/hex; только выбранные `assetId`, `role`, `templateId`, `paletteId` из белого списка.
- **Persistence:** scene JSON в `clientStorage`/plugin data; для версии в файле - метаданные на root frame.
- **Export:** сериализовать готовый vector tree либо экспортировать frame as SVG. Проверять, что не появились `<image>` и base64-raster fills.

## 10. Критерии готовности

- Библиотека содержит все 20 исходных SVG и их метаданные.
- Пользователь может собрать композицию обоими сценариями.
- В результат попадают только библиотечные объекты и их утверждённые фоновые варианты.
- Объект остаётся векторным после вставки и после SVG-экспорта.
- Палитра меняет все связанные цвета согласованно и не ломает контуры/акценты.
- Нельзя вручную растянуть объект или отредактировать его части.
- Работают операции add/move/rotate/duplicate/delete/reorder.
- L и S имеют отдельные шаблоны и safe areas.
- Демонстрация содержит не менее 2-3 композиций: только главные объекты, смесь главных и фоновых, разные палитры/форматы.

## 11. Что передать вместе с разработкой

1. Исходные SVG для 20 объектов и подготовленные варианты `main/background`.
2. Точную таблицу палитр и semantic token map из Figma.
3. Пресеты размеров/безопасных зон для L и S.
4. JSON-манифест ассетов, шаблонов и палитр.
5. Три reference-композиции из исходных материалов для визуальной регрессии.

## 12. Неясности, которые нужно подтвердить до финальной реализации

- точные pixel dimensions форматов L и S;
- точный полный список 20 ассетов и допустимые роли каждого;
- допустимы ли зеркальное отражение и произвольный поворот;
- правила пересечений и минимальные отступы;
- нужна ли автоматическая генерация нескольких вариантов или достаточно одного;
- где должен выполняться AI-анализ метафоры и какие требования к приватности/ключам.
